# extension (serumBrighter)

## Purpose
An Ableton Live extension built on the (beta) Ableton Extensions SDK. It finds a track running
Serum, renders its audio, measures spectral centroid ("brightness"), and iteratively nudges the
filter cutoff until the sound is perceptibly brighter — a closed perception → action loop exposed
as two Live commands (`serumBrighter.brighter`, `serumBrighter.revert`). This folder is the *only*
Ableton-dependent part of a larger demo: the engine/planner/adapter logic it drives is portable TypeScript
that lives one level up, in `../src/*.ts`, and is already tested offline.

## For AI Agents

### Working In This Directory
- Everything `extension.ts` calls — engine, planner, Live adapter, spectral-centroid measurement —
  is portable TypeScript in `../src/*.ts` (one level up, i.e. `ideas/demo/src/`), imported via relative
  paths like `../../src/liveAdapter.ts`. Don't duplicate that logic here or move `extension.ts`
  without updating the imports; new brightening/measurement behavior belongs in `../src/`, not here.
- `manifest.json#entry`, `package.json#main`, and the esbuild `outfile` in `build.ts` must all agree
  (`dist/extension.js`).
- The extension currently runs the hardcoded mock planner (`makeMockPlanner`); swapping in
  `makeClaudePlanner` (model `claude-sonnet-4-6`, guarded on `ANTHROPIC_API_KEY`) is the documented
  one-line path to "go AI" — see `README.md §4`.
- Real (non-typecheck) validation requires a live Ableton rig with extension support enabled
  (Beta build per `.env`'s comment) and the two go/no-go spikes in `README.md §0` passing.

### Testing Requirements
- `npm run typecheck` (`tsc --noEmit`) is the only check runnable without a rig.
- The portable engine has its own offline test suite one level up: `../liveAdapter.test.ts`,
  `../intent.test.ts`, `../wav.test.ts`, `../test.ts` (run with plain `node`, not from here).
- End-to-end validation needs Live: `npm start` builds and launches the Extension Host against
  `EXTENSION_HOST_PATH`, then exercise the context-menu actions on a MIDI track with Serum loaded.

### Common Patterns
- `npm run build` (dev, sourcemaps, unminified) vs `npm run build:prod` (minified, used by
  `npm run package`).
- Dev logs: `npm start` tees the Extension Host's stdout to `.logs/extension-host.log`;
  `npm run logs` tails it (and falls back to Live's own packaged `ExtensionHost.txt`).
